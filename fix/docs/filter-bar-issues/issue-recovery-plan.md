# 筛选栏问题回收方案

## 1. 回收原则

每次只回收一个问题域，保留能够独立验证的最小改动，避免事件修复、样式修复和 observer 改动混成无法定位的版本。

## 2. 代码回收检查

回收每个 Agent 的修改时检查：

- 是否只修改了分配范围内的文件。
- 是否覆盖其他 Agent 或用户的未提交修改。
- 是否保留了 `phx-click`、`phx-value-value`、`phx-target` 和 Alpine 事件属性。
- 是否保证筛选容器和文本翻译幂等。
- 是否引入多个 `.filters-container`。
- 是否改变了非筛选功能。
- 是否影响当前已有的 `src/utils/constants.ts` 修改。

## 3. 功能验收标准

### 3.1 事件功能

- 玩家职业筛选可以改变选中状态或筛选结果。
- 对战职业筛选可以改变选中状态或筛选结果。
- 格式、排名、时间等其他筛选均可正常使用。
- 筛选菜单内部事件节点没有被删除。

### 3.2 渲染表现

- 首次加载不出现明显的原样式闪回。
- 单次筛选操作不出现明显二次闪烁。
- 筛选容器不会反复生成或移动。
- 筛选栏背景覆盖所有换行内容。
- 下拉菜单不会被筛选容器裁剪。

### 3.3 兼容性

- `/decks` 正常。
- `/meta` 正常。
- `/card-stats` 正常。
- `/matchups` 正常。
- 卡组详情页正常。
- 排行榜正常。
- 桌面、窄屏和移动端均正常。

建议 viewport：`1440px`、`1280px`、`900px`、`769px`、`768px`、`480px`。

## 5. 自动化和构建检查

回收前运行：

```bash
pnpm run lint
pnpm run build
```

Chrome MCP 回归还需要检查：

- Console 是否出现新增错误。
- 页面 URL 是否正确更新。
- 筛选选中状态是否保留。
- `.filters-container` 是否只有预期数量。
- `scrollHeight` 和 `clientHeight` 是否一致或符合预期。

## 6. 失败处理

### 职业筛选仍失效

优先检查内部 `[phx-click="add_selected"]` 节点是否存在。如果不存在，回退文本翻译改动，重新设计只替换叶子文本节点的逻辑。

### 筛选生效但仍闪烁

暂时保留安全翻译和 CSS 修复，只回退 MutationObserver 调度改动，重新记录 mutation 来源和执行顺序。

### CSS 修复影响原有页面

保留 DOM 幂等修复，缩小 CSS 选择器范围，优先按页面类型覆盖，而不是扩大全局规则。

### LiveView 更新被拦截

撤销过于激进的 observer `disconnect()`、`takeRecords()` 或 mutation 过滤规则，改为只减少无关 feature 的执行。

## 7. 最终发布门槛

满足以下条件后才合并到测试脚本：

1. P0 职业筛选问题已通过 Chrome MCP 验证。
2. P1 闪烁问题在至少两个页面和三个 viewport 下不再复现。
3. P2 换行背景问题在桌面和移动端不再复现。
4. 卡组、卡牌、基础 UI 翻译无回归。
5. `pnpm run lint` 通过。
6. `pnpm run build` 通过。
7. 所有剩余风险已记录在回归结果中。
